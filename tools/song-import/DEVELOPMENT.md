# Устройство утилиты добавления песен

Этот документ описывает последовательность работы утилиты и назначение вызываемых файлов. Пути указаны относительно корня проекта. Инструкция по запуску находится в соседнем `README.md`.

## 1. Запуск

`tools/song-import/add-song.cmd` переходит в корень проекта и запускает:

```sh
node tools/song-import/add-song.js
```

После завершения окно остаётся открытым благодаря `pause`, чтобы пользователь мог прочитать результат. Другой способ запуска — `npm run add-song` из корня проекта.

## 2. Чтение ссылки и проверка дубликата

Главный файл `tools/song-import/add-song.js` получает ссылку из аргумента командной строки или запрашивает её в консоли.

Он использует функцию `videoId()` из `tools/song-import/song-import.js`, которая проверяет адрес YouTube и извлекает ID видео. Поддерживаются обычные ссылки `watch?v=`, короткие `youtu.be`, а также ссылки `shorts`, `embed` и `live`.

Затем главный файл читает `content/songs.json` и ищет ID среди основных видео и альтернативных версий (`alt`). Если видео уже есть, обычный запуск прекращается. Для продолжения обработки существующей записи используется `--resume`.

## 3. Получение названия ролика

Для нового видео `add-song.js` запрашивает сведения через YouTube oEmbed. Если получить название не удалось, он пытается прочитать заголовок страницы ролика. На каждый запрос установлен тайм-аут 15 секунд.

Функция `songName()` из `tools/song-import/song-import.js` удаляет пометки вроде «Караоке» и пробует разделить название ролика на исполнителя и название песни по тире. Результат используется только как предложенное значение: пользователь должен проверить и при необходимости исправить его. Если сведения получить не удалось, их можно ввести вручную.

## 4. Подтверждение сведений

Главный файл запрашивает исполнителя и название песни. Значение в квадратных скобках принимается нажатием Enter.

Если сочетание исполнителя и названия уже есть в каталоге, без учёта регистра, утилита предлагает добавить видео в `alt` этой песни. Новая строка песни при этом не создаётся.

Для новой песни дополнительно запрашиваются:

- язык — `ru` или `en`; предложенное значение определяется по наличию кириллицы в исполнителе и названии;
- раздел — выбирается из разделов существующего каталога; по умолчанию предлагается «Русская поп-музыка» или «Зарубежная музыка» в зависимости от языка;
- жанр — свободный текст, по умолчанию «Поп».

Перед записью утилита запрашивает окончательное подтверждение добавления.

## 5. Сохранение исходных данных

После подтверждения `add-song.js` записывает в `content/songs.json` ID, исполнителя, название, жанр, раздел и язык. Для альтернативной версии он добавляет ID видео в `alt` существующей песни.

## 6. Загрузка и проверка текстовых подсказок

Если у основного ID песни ещё нет ни куплета, ни припева, запускается:

```sh
node scripts/fetch-lyrics.js --review --only ID_ПЕСНИ
```

Загрузчик ищет совпадение и по исполнителю, и по названию. Загрузчик предлагает полный первый куплет и припев только при явной разметке обоих разделов в источнике. Сборщик сохраняет строки и повторы из исходного JSON. Загрузчик записывает его в `content/lyrics.json` по основному ID песни только после явного ответа «да».

Сверьте все строки первого куплета и припева с караоке. Для существующей подсказки, в том числе при `--resume`, подтверждение запрашивает сам импортёр. Если вариант отклонён или точного совпадения нет, исправьте `content/lyrics.json` вручную и продолжите через `--resume`.

## 7. Первая сборка каталога

Запускается `scripts/build-catalog.js`. Он читает:

- `content/songs.json`;
- `content/lyrics.json`;
- `content/embeds.json`, если файл доступен.

Сборщик формирует `data/catalog.js` — модуль с массивом `SONGS`, который читает сайт. В него входят сведения о песнях, подсказки, поисковые поля и признаки ограничения встраивания.

Первая сборка нужна до проверки видео: `scripts/check-embeds.js` импортирует песни из готового каталога.

## 8. Запуск временного сервера

Главный файл запускает `scripts/dev-server.js` с переменной окружения `PORT=0`. Сервер выбирает свободный порт и выводит локальный адрес. Утилита считывает этот адрес; ожидание запуска ограничено 10 секундами.

Временный сервер нужен для проверки плеера и останавливается при завершении главного файла.

## 9. Проверка встраивания видео

Утилита определяет путь к Chrome через `chromePath()` из `tests/support.js`. Используется заданный `CHROME_PATH` или установленный тестовый Chrome; если файл не найден, выбирается стандартный путь установки Google Chrome в Windows.

Затем запускается:

```sh
node scripts/check-embeds.js --only ID_ВИДЕО
```

Главный файл передаёт дочернему процессу переменные окружения:

- `CHECK_BASE_URL` — адрес временного сервера;
- `CHROME_PATH` — путь к браузеру.

`scripts/check-embeds.js` открывает Chrome через Puppeteer и загружает `scripts/embed-check/index.html`. Страница подключает YouTube IFrame API и `scripts/embed-check/embed-check.js`. Функция `checkBatch()` создаёт настоящий YouTube-плеер и пробует воспроизвести видео.

Отчёт сохраняется в `content/embeds.json`, с сохранением результатов для других видео.

Главный файл принимает следующие результаты:

- `status: "ok"` — подтверждено воспроизведение;
- ошибка YouTube `101` или `150` — автор запретил встраивание, видео будет открываться на YouTube.

Другие результаты, включая тайм-аут, считаются незавершённой проверкой. Утилита останавливается и предлагает повторить запуск с `--resume`.

## 10. Итоговая сборка и завершение

После успешной проверки снова запускается `scripts/build-catalog.js`. Теперь `data/catalog.js` учитывает свежий результат из `content/embeds.json`.

Утилита сообщает об обновлении локального каталога, выключает временный сервер и закрывает консольный ввод. Пользователь обновляет страницу локального сайта, чтобы увидеть изменения.

## Ошибки и продолжение работы

По умолчанию дочерние скрипты, запускаемые через функцию `run()`, ограничены 180 секундами. Интерактивный просмотр подсказки ждёт ответа без общего тайм-аута. Ошибка или превышение времени прекращает последовательность.

Записи сохраняются поэтапно; автоматического отката нет. После ошибки утилита выводит команду продолжения:

```sh
node tools/song-import/add-song.js --resume "https://www.youtube.com/watch?v=ID_ВИДЕО"
```

Если ID уже есть в каталоге, `--resume` пропускает ввод сведений и добавление записи, затем повторяет проверку текста, сборку и проверку видео. Если сохранён только куплет или только припев, добавьте недостающий раздел вручную. Дополненный текст будет показан для подтверждения.

Без `--resume` повторная ссылка отклоняется как дубликат.

## Проверки и границы ответственности

Тесты утилиты находятся в `tools/song-import/tests/`:

- `import.test.js` проверяет разбор ссылок и названий;
- `workflow.test.js` проверяет сценарий добавления, отказ от дубликата, продолжение после ошибки и отклонение удалённого параметра `--publish` на временных данных с подменёнными внешними операциями.

Они входят в общий `npm test`. Сам запуск добавления песни не запускает полный набор тестов сайта, не выполняет команды Git и не публикует изменения.

Общие загрузчик текстов, сборщик каталога и проверка встраивания остаются в `scripts/`, поскольку используются и вне утилиты. Зависимости устанавливаются в корне проекта; отдельного `package.json` у утилиты нет.
