# Проверки пользовательских сценариев

Запуск: `npm ci`, `npm run test:browser`, затем `npm test`.
Chrome for Testing закреплён в `support.js`; установленный в системе Chrome не нужен.
`CHROME_PATH` позволяет отдельно проверить другой браузер, но такой запуск уже не
воспроизводит закреплённое окружение. После `npm ci` браузер нужно установить заново.
Сервер получает свободный порт; параллельные прогоны не делят порт и хранилище.
Используются встроенный `node:test` и Puppeteer Core.

`npm run test:mutations` намеренно ломает семь участков приложения только в ответах
тестового сервера: поиск, заголовок выбранной песни, паузу, слова, защиту от повтора,
языковой фильтр и сортировку.
Для успеха аудита каждая поломка должна вызвать конкретную ожидаемую ошибку теста.
Сбой запуска браузера не засчитывается как обнаруженная поломка. Файлы приложения
не изменяются. Диагностика этих ожидаемых падений остаётся в `tests/artifacts/`.

В GitHub Actions набор запускается при каждом push, в pull request и вручную
через Actions → Tests → Run workflow. Workflow `tests.yml` устанавливает
зависимости через `npm ci`, собирает каталог, устанавливает закреплённый Chrome
и выполняет обычные тесты и аудит поломок на Windows с Node.js 22.
При ошибке сохраняется артефакт `test-diagnostics` со снимками страницы, HTML
и описанием ошибки. Бейдж в корневом README показывает результат push в `main`;
по нажатию открываются прогоны с журналами проверок. До первого прогона статуса нет.

`logic.test.js` проверяет настоящие функции поиска и очистки текста на входах
с вручную заданными ожидаемыми результатами, а также сравнивает собранный каталог
с исходными метаданными. Он не импортирует функции приложения для расчёта ожиданий.

`ui.test.js` проверяет интерфейс и регрессии вёрстки; группы запускаются в отдельных
контекстах браузера. `scenarios.js` проверяет реальный каталог, все пересечения
фильтров, сортировки, слова и пользовательские потоки. Ожидаемые наборы ID считаются
из метаданных, без вызова рабочего фильтра или чтения ожидаемого результата из DOM.
Количество песен, ID выбранного видео и число альтернатив не зафиксированы.

`player-contracts.js` использует небольшой явно заданный каталог для граничных
случаев: запрет встраивания, три версии с разной доступностью, отсутствие текста,
только припев и специальные символы. На нём также проверяются меню и подсказки.
Это тестовые входы, а ожидаемые URL, строки и состояния заданы независимо.
Основные сценарии продолжают работать на настоящем каталоге.

`upgrade.js` моделирует предыдущий релиз с устаревшими названиями песен и отдельным
именем кеша. Он выполняет настоящий service worker приложения и проверяет переход
на текущие данные. Это модель обновления, а не запуск исторической версии из Git.

Любая проваленная проверка или ошибка JavaScript завершает `npm test` с кодом 1.
Повторный запуск для скрытия ошибки не используется. При падении отчёт сохраняется,
а остальные независимые группы продолжают выполняться.

## Границы покрытия

Это покрытие перечисленных сценариев в Chromium, а не метрика 100% строк/ветвей.
Во всех браузерных тестах Manrope берётся из закреплённого локального пакета;
сетевой Google Fonts не используется. Внешний YouTube заменён iframe, который
реально получает команды через `postMessage` и сообщает об их получении.
Функция отправки команд приложения не подменяется. Это проверяет действия
приложения, но не подтверждает звук, доступность ролика, рекламу и работу YouTube.
Для проверки текущих ограничений видео используйте `npm run check-embeds`
при запущенном сервере и проверяйте фактическое воспроизведение вручную.

Офлайн-проверка относится к уже посещённому сайту; видео и внешние шрифты
не становятся доступными без сети. Firefox, Safari, установка PWA, экранные
дикторы и реальные мобильные устройства этим прогоном не проверяются.

`npm run screenshots` — отдельный вспомогательный скрипт снимков при работающем
`npm start`. Он не сравнивает изображения с эталоном и не заменяет тесты.
